# 第三轮：经验系统在研究方向中的重新定位

## 结论先行

我现在不再把经验系统视为双门主线旁边的普通“supporting memory”。用户澄清后的系统具有明确的算法职责：它在跨已结算 optimizer decision episode（当前代码中的 `research_attempt` / Candidate settlement，并延续到后续 generation）学习 Harness optimizer 的搜索先验；双门负责单个研究 episode 内的实验信用分配，经验系统负责 episode 之间的搜索空间更新。两者组成同一研究闭环，但承担不同的因果问题。当前 Controller 只有 Candidate promotion 后才递增 `generation`，因此论文不能把每次失败后的重试误称为新 generation。

建议的总方向名称调整为 **Evidence-Gated and Experience-Guided Harness Evolution**。其中：

1. **单个研究 episode 内：先验证再编译。** 在冻结 Prefix 上用不可部署 soft intervention 检验可证伪假设；Evidence Gate 通过后蒸馏机制；若机制要求 Student 承担语义职责，再独立做 target-Student realizability gate；最后才生成 Candidate。
2. **已结算 episode 之间：由验证结果更新搜索先验。** reviewer/gate 的 reject 或 revise 轨迹即时触发 Experience Candidate；同时，Attempt Ledger 确定性记录 support/pass、reject/revise、feasibility、conformance、promotion 与 global regression 等所有有研究意义的 typed verdict 和终态，避免只从失败学习的选择偏差。经验不是全局广播，而是写成有 provenance、scope、consumer 和 invalidation 条件的定向 artifact，在后续 attempt/candidate episode 中生效并延续到后续 generation，减少重复的能力越界、角色失误和方向重走。

因此经验系统不是“给 agent 加一个更长的上下文”，而是把历史验证结果变成 optimizer 的、按职责分区的控制信号。

## 三类经验的精确定义与消费者

| 经验类型 | 唯一主要消费者 | 写入证据 | 作用 | 不允许的用法 |
|---|---|---|---|---|
| Student 能力边界 | Hypothesis Researcher | Hook/Responsibility Feasibility 的通过与失败、真实 Prefix probe、后续 adherence/conformance 结果 | 在提出方向时降低职责难度、提出较低语义负担的 mechanism requirement 或建议 ownership，剪去已反复证明超出固定 Student 能力的机制空间，也保留已证实能力的正边界 | 不得直接令 Evidence Reviewer 接受/拒绝当前假设；不得成为永久模型标签；不得把原始能力经验投影给其他角色 |
| Teacher 角色工作经验 | 产生问题的同一 Teacher role；并进一步绑定 teacher model、role contract、prompt/input 版本 | 下游 reviewer 的 typed obligation、输入缺失、误读、过度推断、contract violation、通过样例及修订后的结果 | 动态补足该角色不稳定的 prompt/输入，减少相同角色重复犯同类错误，并保留可靠做法 | 不向其他角色广播；不同 Teacher 模型或 prompt 版本之间不得默认无损迁移 |
| 已实验方向记录 | Hypothesis Researcher | failure fingerprint、hypothesis、trial coverage、正负 intervention evidence、mechanism、feasibility、candidate effect 与最终状态 | 形成“问题—思路—证据—结果”的搜索地图，避免重复提出同一方向，并识别尚未覆盖的邻域 | 不得把一次失败标为整类方向永远无效；不得只存结论而丢失支持与反证 |

这里的核心不是访问控制本身，而是每条经验的**责任归属**。一个 Evidence Reviewer 的否决，不应该变成所有角色都读到的模糊教训；它可被分别归因为 Student 能力、特定 Teacher 角色工作错误和已实验方向结果，再只影响真正能据此改变决策的角色。三类不是互斥标签：同一轨迹可以生成多个有独立证据与 consumer 的 Experience Candidate，Curator 不得强迫三选一。

Student 能力经验仍然只由 Researcher 消费。Researcher 可以把检索结果转成当前 Hypothesis/Mechanism brief 中显式的 responsibility ceiling 或 lower-difficulty requirement；Distiller 只看到这个正常的上游设计合同，而不读取长期能力经验。若本次 Hook Feasibility Gate 失败，Distiller 可以接收该次 reviewer 的 revision obligation，这是当前轨迹的类型化回流，不是跨 episode 的经验投影。这样既让约束作用到机制设计，又不破坏用户指定的消费者边界。

## 为什么这比上一版更重要

上一版把经验系统降为 supporting subsystem，是因为当时的描述更像“reject 后总结三类 memory”。在用户明确消费者之后，系统呈现出两个此前没有充分表达的研究价值。

第一，它是 **跨 optimizer episode 的信用分配延伸**。双门能解释“本次为什么不应编译”，但如果下一 attempt 或后续 generation 的 Researcher 又提出同样超出 Student 能力的 hook，实验成本仍会重复发生。Student capability experience 把 feasibility verdict 变成下一轮 hypothesis prior，从而把局部归因转化为长期搜索效率。

第二，它把 **Teacher 的可变性**纳入系统模型。不同 Teacher 模型、prompt 版本和输入合同会产生不同理解；对应角色经验并不是静态 prompt engineering，而是由该角色历史 rejection 动态形成的 contract supplement。它学习的是“这个角色在当前配置下怎样更可靠地履责”，而不是任务世界知识。

第三，方向地图把整个演化流程从候选列表变成 **有证据的研究空间地图**。它不仅记录 patch 成败，而是记录从失败方向、局部 intervention、机制、Student feasibility 到 Candidate effect 的完整链条，允许 Researcher区分“假设失败”“Student 无法执行”“实现偏离”和“全局效果退化”。

## 文献边界：哪些不能再声称新颖

专项检索明显收紧了主张。

- G-Memory 已研究 cross-trial、agent-specific collaboration memory；Intrinsic Memory Agents 已使用 role-aligned memory。因此“经验只给指定角色消费”本身不是新颖点。
- LLMA-Mem 的 episodic、procedural、transactive memory 与方向记录、角色经验、能力边界高度同构。因此三类经验的 taxonomy 不是贡献。
- ExpeL 已从 agent experience 中抽取自然语言 knowledge；A-MEM 已做动态组织、链接和更新。因此总结、检索、更新均不能单独主张。
- Auto-Robotist 已将带正负证据的搜索轨迹转为可审计 skill library，并保留探索分支。因此“search becomes memory”也不是本项目独有。

仍可能成立的边界是以下联合协议：经验属于**外部 Harness optimizer 的研究角色**，不是 Student 的 solve-time memory；它由分离的 hypothesis/evidence/feasibility/conformance/candidate verdict 写入；每类经验有严格 consumer、配置作用域和失效条件；它只改变后续搜索优先级，不替代当前 generation 的实验 Gate；同时必须用探索旁路和定期复查测量 false pruning。

## 修订后的三项联合假设

### H1：Pre-materialization Evidence Gate

在生成可复用 executable Candidate 之前，用冻结 Prefix 上的 repeated matched no-op continuation 与 soft-intervention continuation 检验 implementation-independent behavioral hypothesis，能否改善 downstream Candidate effect 的预测并减少无效完整评估。

### H2：Target-Student Responsibility Realizability Gate

H2 拆成两个可分别失败的子假设：

- **H2a（预测）**：对 Evidence-backed mechanism 中归 Student 所有的 recognition、decision、adherence 与 fallback 职责做独立 Prefix probe，能否预测 shadow/in-loop 的真实可执行性与 parse failure。
- **H2b（路由）**：基于 H2a 的结果在 reject、simplify、deterministic lowering 和 ownership reassignment 间路由，能否相对固定 lowering 策略提高可实现 Candidate 比例、减少完整评估浪费并保持 held-out utility。

### H3：Verification-Grounded Role-Scoped Research Experience

把所有有研究意义的 typed verification verdict 与终态汇总为只投影给指定消费者的 Student capability boundary、Teacher role work experience 和 experiment-direction map，能否在跨 settled optimizer episode、并延续到后续 generation 的固定预算搜索中降低能力越界提案、同角色重复错误和重复方向，并提高 useful Candidate yield；同时把 false suppression 控制在预注册的非劣界限内。reject/revise 负责即时触发总结，但不是唯一写入源。

H3 是待检验贡献，不是已有结论。用户所说的收益是有充分机制理由的预期，但也可能因早期弱证据、配置漂移、错误归因或过度 exploitation 而失败。

## H3 必须怎样实现才可研究

每条经验至少包含：`experience_type`、`producer_verdict_ref`、`supporting_artifact_refs`、`contradicting_refs`、`consumer_role`、`student/teacher/prompt/contract scope`、`evidence_grade`、`status`、`retry_condition`、`invalidated_by`、`usage_receipt`。`evidence_grade` 必须由可复算规则产生（例如单次局部 observation、重复 Prefix 支持、跨 case 支持、Candidate-level 支持/反证），不能由 Curator 自由输出浮点置信度。单次 reject/revise 只能生成 provisional Experience Candidate；只有确定性的重复证据、后续终态或独立 reviewer 条件才能 promote、contradict 或 supersede，不能由同一 Teacher 自我总结后自我确认。

具体作用域如下：

- Student capability：绑定 Student model/API/schema、base harness、task family、responsibility class。model、tool/API schema 或责任合同的不兼容变化是 hard mismatch 并直接失效；base harness、task distribution 或 decoding 的变化是 soft drift，降级为 provisional 并强制 recheck。
- Teacher role experience：绑定 `role_id + teacher_model + role_contract_version + base_prompt_digest + input-view digest`；experience projection 另有独立 digest，避免注入经验后 prompt digest 自我变化导致无法命中。model/role contract/input schema 不兼容是 hard mismatch；base prompt 小改或输入分布变化是 soft drift，只允许试探性检索并触发 recheck。
- Direction map：绑定 failure fingerprint、Student/harness/evaluator 版本和 task family；状态至少区分 `untested / locally_supported / locally_refuted / student_infeasible / implementation_failed / globally_regressed / useful`。

经验只能作为 Researcher/role 的检索上下文与排序先验，不能作为 Evidence Gate 的替代证据。系统必须保留固定比例的 exploration bypass，并对高影响的 negative experience 做定期 recheck，避免一次失败永久封闭一片空间。

经验在 Attempt/Candidate settlement 后由独立的 Curator WorkItem 写入，只能从下一个 optimizer decision episode 开始生效，不得回写并影响产生它的同一条未结算轨迹。正式实验还必须预注册最少 settled attempts、experience writes 和 retrieval opportunities，而不能只用当前最多五次且 promotion 才递增的 `generation` 数表达学习机会。

## 独立实验协议

实验单位应是完整的 multi-generation evolution run，而不是单条经验。所有 H3 条件冻结同一个 H1/H2 optimizer、相同门禁协议、Student、Teacher 配置、任务流、初始失败集、总 token/rollout/完整 Candidate evaluation 预算和随机种子集合；每个条件使用独立 Store，经验不得跨 split、跨种子或跨条件泄漏。比较：

1. no experience；
2. global/shared unstructured experience；
3. generic role-local memory（覆盖现有 role-specific memory 先例）；
4. ExpeL-style unscoped experiential insight extraction；
5. G-Memory/Intrinsic/LLMA-Mem-style agent-specific or role-local memory；
6. P012 DREvo-like function-anchored、state-recalibrated historical evidence；
7. P020 Auto-Robotist-like evidence-grounded positive/negative search-trace skill library；
8. verification-grounded role-scoped experience（完整 H3）；
9. capability-only、teacher-role-only、direction-map-only 消融；
10. 相同 role scope 但由普通轨迹摘要写入；相同 evidence-grounded record 但移除 verification-stage provenance；完整 H3 去掉 invalidation/recheck 或 exploration bypass；
11. stale/corrupted experience 与 exploration-bypass 压力测试。

主要指标：每 generation 的 capability-violating hypothesis rate、duplicate direction rate、同一 role revision obligation recurrence、full Candidate evaluation 数、time/tokens to first useful Candidate、useful Candidate yield per budget、held-out final utility、false-pruning rate 和 override/recheck 恢复率。辅助指标：experience retrieval/usage/change receipt、跨同模型 Teacher 与跨不同 Teacher 的迁移差异、direction-map coverage。每条被用到的经验都要能追踪“检索到—实际改变输出—改变后结果”的链条。

false pruning 需要可观测的反事实协议，而不能只根据模型自报。每个 Researcher episode 先冻结 blinded proposal shortlist，再注入经验生成 memory-conditioned shortlist；对被 negative experience 降权或移除的方向按固定概率抽样，走完整 Gate/编译/评估旁路。false pruning 定义为“被经验抑制、但在无经验或 bypass 审计中满足预注册 useful 条件”的比例。配对抽样单位、随机种子、bypass 比例和 recheck 频率均在 Goal 阶段预注册。

只有 H3 相对 no-memory、shared-memory、generic role-local memory、DREvo-like historical evidence 和 Auto-Robotist-like search memory 都显示额外的跨 episode 效率或归因价值，且 held-out utility 不下降、false pruning 受控，才能把经验系统写为并列方法贡献。否则它应退回工程功能或仅报告负面结论。

## H1/H2 的独立识别与 Gate 误拒估计

H1 的局部试验是冻结原始 Student Prefix 后的 repeated matched **no-op continuation** 与 **soft-intervention continuation** 两臂；原始 rollout 只负责提供 Prefix，不是第三个未经匹配的效果臂。对预注册比例的 Gate-rejected mechanisms 仍执行盲编译与完整评估，以估计 false rejection，并检验局部 evidence 对 Candidate effect 的校准与排序能力。

单 episode 门禁阶段至少比较 candidate-first、H1 only、H2 only（或对同一 evidence-backed mechanism portfolio 离线评估 H2）和 H1+H2。H2a 分别报告 recognition、decision、adherence、fallback 与 parse failure 的预测/校准；H2b 比较 always-Student、always-deterministic、无 feasibility routing 与基于 probe 的 adaptive routing。任一 H 独立失败时只撤回对应贡献，不能用整体系统收益替代它的因果证据。

进入 `cvpr-goal` 时还需预注册 H3 的 held-out non-inferiority margin、最大 false-pruning rate 和 minimum override/recheck recovery；当前 Start 阶段不虚构具体阈值。

H3 必须在 H1/H2 的标签、Gate 规则和 pipeline 经独立验证后再开始正式比较；所有 H3 变体冻结同一 H1/H2。若 H1/H2 verdict 本身无效，generic memory 即使有收益，也不能归因为 verification-grounded experience。

## 当前代码事实与缺口

当前代码仅预留 `historical_experience` 输入，但 Controller 仍传空列表；没有 Curator、Experience Store、Attempt Ledger、role projection、版本失效和 usage receipt。因此 H3 目前是确定要实现、但尚无实证支持的研究分支。现有 typed reviewer obligations、append-only journal、artifact lineage 和 research-attempt routing 为写入 provenance 提供了基础；它们不等于经验系统已经存在。

最小实现还包括：append-only/versioned ExperienceRecord；确定性的 scope/top-k/token-budget projection service；Researcher 和对应 Teacher role 的不同结构化输入；retrieved/rendered/cited/ignored IDs 与 output digest receipt；固定种子的 exploration/recheck scheduler；resume/idempotence、contradiction、supersession、scope invalidation、split leakage 和 stale-memory 测试。当前 Candidate Reviewer 的 `list[str]` 不能直接复用为这些角色的正式合同。

预算方面，当前 Controller 只在 WorkItem 启动前检查累计 token，单项完成后仍可能突破 soft budget。正式 H3 实验前必须实现 reservation/commit/refund 的 hard budget ledger，把 Curator、检索、经验上下文、Trial、Feasibility 与完整 Candidate Evaluation 全部计费；结果同时按累计 token、rollout、完整 Candidate evaluation 数和 settled opportunities 呈现。

## 建议的最终研究表述

本研究不应写成“先验证机制，再附加记忆”。更准确的表述是：**我们研究一种双时间尺度的 Harness 自进化范式：在单个研究 episode 内，用局部干预证据与 target-Student realizability 决定什么机制值得编译；在已结算 episode 之间，把各验证层的结果转化为有作用域、按角色投影且可失效的研究经验，更新后续假设搜索的优先级，并将效果延续到后续 generation。** 前者解决 Candidate 生成过早与错误归因，后者解决同一无效区域和角色错误被跨 attempt/generation 重复探索。最终贡献是否成立，分别由 H1/H2 的门禁实验和 H3 的 multi-episode/multi-generation 经验消融决定。
