## 1. 重新表述后的唯一主问题

我们准备研究：

> 当固定小模型 Student 的 Harness 自进化面对一个失败方向时，先在冻结 Prefix 上用可撤销、不可部署的 soft intervention 验证行为假设，再把证据蒸馏为 implementation-independent mechanism，并在编译前验证 Student 对机制语义职责的可实现性，是否能比 candidate-first evolution 更有效地发现、归因和复用可执行机制？

这里的两个核心命题必须同时出现：

1. Harness 假设先作为局部干预接受实验验证，再成为持久化 Patch。
2. 得到证据支持的机制先接受 target-Student realizability test，再被编译为 runtime control。

因此，原 IDEA-001R 与 IDEA-002R 应合并为一个主 IDEA。IDEA-004R 是验证第一道门的方法，IDEA-005R 是把失败归因送回正确阶段的控制与学习设施，IDEA-003R 只在多 realization transport 具备真实实现时保留为扩展。

## 2. 简化后的工作流

    真实 Student Failure
      -> 可证伪 Hypothesis
      -> 冻结 Prefix
      -> Baseline continuation / Teacher soft intervention
      -> 配对、重复的局部证据
      -> Evidence Gate
      -> Implementation-independent Mechanism
      -> Student Responsibility Feasibility
      -> Compile Candidate
      -> Conformance + Full Evaluation

    任一 Reviewer reject 或 revise
      -> Typed Revision Route
      -> Experience Candidate
      -> Evidence-backed Experience Curator
      -> 按角色和范围投影到后续研究

这条链的研究单位不是完整 Candidate，而是：

\[
(\text{frozen prefix},\ \text{reversible intervention},\ \text{paired outcome})
\]

Candidate 仍然必须接受完整同口径评估，但它不再承担最早的假设筛选。

## 3. 五个候选原来分别在讲什么

### IDEA-001R

它回答“先试机制、后写 Patch”是否值得。它是总框架，不是某一个 Reviewer 或某一个工具。

### IDEA-002R

它回答“Teacher 认为机制正确，但小 Student 是否真的能执行其中的语义判断”。它是总框架的第二道核心门，不应被写成与 IDEA-001R 竞争的另一篇论文。

### IDEA-003R

它回答同一个 mechanism 应编译为 prompt、deterministic hook、hook_model、tool 还是 parser。它只有在我们真实实现多个 lowering 并比较 transport drift 时才是独立贡献。

### IDEA-004R

它回答局部 intervention 怎样测才可信。same-prefix 本身不能消除随机性，所以需要重复双臂 continuation、随机化顺序和层级统计。它是 IDEA-001R 的测量协议。

### IDEA-005R

它原本只回答“失败应该打回 research、mechanism、feasibility 还是 implementation”。加入经验系统后，它还要回答“这次打回能否形成有来源、有限范围、可修正的跨 Run 经验，供后续角色避免重复错误”。它是闭环学习设施，但默认不单独承担主 novelty。

## 4. 经验系统如何纳入

我们把 Reviewer 的 reject 或 revise 看成经验触发信号，但不直接当成事实。一次打回可能来自 Reviewer 误判、API 故障、格式偶发失败或单案例噪声。安全的链路是：

    Reject / Revise Event
    -> deterministic Experience Candidate
    -> 在 Research Attempt、Candidate 或 Generation 结算点归纳
    -> 带证据与适用范围的 Research Experience
    -> role-specific projection
    -> 后续角色读取并记录使用回执

经验分成用户提出的三个主视图。

### 4.1 Student 能力边界

记录 Student 或 Hook Model 在什么 scope 下能否执行 recognition、three-way decision、state inference、fallback 和 structured output。普通 rollout 只能支持 Student Agent 层面的观察；只有独立 probe 或跨 Harness 对照才能归因到 Student Model。

### 4.2 Teacher 角色工作经验

记录 producer role 的输出为何被 consumer role 打回，以及下次必须补什么。例如 Mechanism Distiller 输出没有规定 uncertain 的 phase-local fallback，Compiler 因此无法实现。它不记录泛化的“写得更清楚”，而记录 producer、consumer、failure layer、obligation、scope 和 artifact refs。

### 4.3 已实验方向记录

用 Attempt Ledger 记录 direction fingerprint、hypothesis、mechanism、样本范围、到达阶段、终态、拒绝原因、证伪条件和何时值得重试。能确定性生成的字段不交给模型总结。

每条可复用经验至少需要：

    kind
    status: provisional | confirmed | contradicted | superseded
    scope
    claim
    observation
    action
    does_not_cover
    supporting_refs
    contradicting_refs
    source_roles
    fingerprint

经验只能提示历史事实、风险与检查点。它不能补足当前 Trial coverage，不能直接决定 Promotion，也不能把历史 reject 变成不可绕过的禁令。

## 5. 经验系统在研究中的位置

我们建议把经验系统定义为第三项支持性贡献：

> 一种由 typed rejection trajectory 触发、由证据治理、按 Student 能力、角色协作和实验方向分层投影的跨 Run Research Experience。

我们暂时不把“有 memory”本身作为新颖性主张。近期 Harness/agent evolution 已有历史轨迹、candidate archive、failure memory 和 evidence recalibration 的邻近做法。我们能检验的差异是：经验是否保持与当前证据门的边界，是否按 failure layer 与 role scope 投影，以及是否减少重复研究而不造成错误自我强化。

## 6. 需要新增的经验消融

在统一 Candidate-first 与 Evidence-Gated 主实验之外，我们增加：

    No historical experience
    vs. Unstructured rejection summary
    vs. Typed evidence-backed role projection

预注册指标：

- duplicate direction rate；
- repeated failure rate；
- 到达同一 reject layer 的修订轮数；
- total Teacher/Student tokens 与 wall-clock；
- useful Candidate yield；
- stale or incorrect experience 导致的 false suppression；
- 经验检索命中后实际是否改变角色输出，以及改变后结果是否改善。

如果结构化经验没有减少重复失败或成本，或者错误、过期经验抑制了本来可行的方向，我们就不应声称经验系统带来研究效率收益。

## 7. 重构后的贡献层级

主贡献：

1. Pre-compilation intervention testing：在持久化 Candidate 之前验证行为假设。
2. Target-model realizability gating：在编译前验证 Student 对语义职责的可实现性。

方法与测量贡献：

3. Matched repeated prefix evidence：测量局部机制证据及其到 Candidate effect 的 transport。

支持性系统贡献：

4. Evidence-to-mechanism separation 与 conformance boundary。
5. Attribution-grounded revision routing 与 evidence-backed experience consolidation。

我们不声称 external Teacher、falsifiable hypothesis、Prefix-Fork primitive、Candidate screening、typed trace、multi-agent role 或 memory 本身是首次提出。
