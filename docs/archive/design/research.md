# 研究思路

## 文档职责

本文档说明 Search Harness 项目的研究动机、核心问题、方法假设和第一阶段研究边界。

系统结构、运行闭环和模块职责见 `overview.md` 及各专题文档。本文档不展开具体接口、Patch Schema 或执行流程，只回答“为什么这样做”和“希望验证什么”。

## 研究背景

真实部署场景中，小基础模型常常因为成本、延迟、私有化部署和资源约束而被使用。

但小模型直接运行在高自由度 Agent Loop 中时，容易暴露出一组系统性缺陷：

- 工具调用不稳定；
- 输出格式和 schema 遵循能力不足；
- 搜索深度不足，过早给出答案；
- 难以发现和修复自己的错误；
- 多步证据整合能力不足；
- 对停止时机、重试时机和验证时机判断不稳。

这些问题不一定只能通过训练模型本身解决。另一种可能路径是：在模型外部增加更适合该模型的结构化支持，让小模型在更明确、更可控的 Harness 中完成任务。

## 核心研究问题

本项目希望验证：

> 在不训练 Actor 模型、不修改 Agent Core Loop、且不依赖外部强模型在线参与的条件下，能否通过自动进化模型外部的 Harness，稳定提升小模型的 Search Agent 能力？

这里的 Harness 指模型外部的运行支持层，包括但不限于：

- prompt；
- tool；
- parser；
- validator；
- memory；
- workflow extension；
- controller policy；
- retry policy；
- schema repair；
- review gate。

## 方法动机

本项目不把外部强模型用于最终在线推理，而是把它用于离线适配阶段。

这里的“离线适配阶段”指：不处于最终部署系统的实时推理路径中，但可以运行实验、回放轨迹、执行 Prefix-Fork、评估候选 Patch 的阶段。

核心动机是区分两种能力来源：

1. 外部强模型在线代做任务；
2. 外部强模型离线发现结构。

前者可以直接提高任务表现，但最终系统仍依赖强模型。后者更接近本项目关心的问题：强模型能否作为离线研究员或编译器，观察小模型失败、探索有效干预，并把这些干预固化成小模型可以独立使用的 Harness。

因此，外部强模型的价值不应体现为“替 Actor 找答案”，而应体现为：

- 发现 Actor 的稳定失败模式；
- 设计非题目相关的局部干预；
- 通过 Prefix-Fork 验证干预是否有效；
- 将稳定有效的干预编译为 Registry Extension；
- 在审计和评估约束下迭代 Harness。

## 软干预到硬化

项目采用“Soft Intervention 到 Hard Harness”的研究路径。

离线阶段，外部强模型可以在受控接口下提出局部指导或审阅意见，例如：

- 提醒 Actor 检查工具输出格式；
- 要求 Actor 在回答前确认是否已有足够证据；
- 指出当前推理步骤缺少验证；
- 建议触发某类通用 retry 或 review 逻辑。

这些干预必须是非题目相关的，不能包含具体 query、实体、答案线索或证据路径。

如果某类软干预在多个样本、多个 Prefix 或多次采样中稳定有效，它可能对应一个可硬化的 Harness 组件，例如：

- validator；
- parser repair；
- controller policy；
- workflow extension；
- review gate；
- prompt rule；
- retry policy。

最终目标不是长期保留外部强模型干预，而是让有效干预逐步转化为可审计、可版本化、可回滚的 Registry Extension。

## 研究假设

本项目基于以下待验证假设。

### 小模型需要更强的外部结构支持

小模型在自由 Agent Loop 中的失败，很多不是单点知识缺失，而是执行结构不稳定。

如果外部 Harness 能提供更明确的格式约束、检查点、重试策略和流程引导，小模型可能在不训练的情况下获得更好的 Search Agent 表现。

### 不同模型可能需要不同 Harness

不同基础模型在指令遵循、工具调用、长上下文利用、反思、停止判断和格式稳定性方面存在差异。

因此，适合一个模型的 Harness 不一定适合另一个模型。后续多模型实验可以验证 Harness 是否呈现可识别的模型特异性。

### 外部强模型更适合离线发现结构

强模型具备更好的失败分析、归因、局部实验和抽象能力。

本项目假设，这种能力更适合用于离线发现和编译结构，而不是在部署阶段持续参与推理。

### 有效软干预可以被硬化

如果一种干预只在单个样本上有效，它可能只是偶然修补。

如果一种干预跨样本、跨 Prefix、跨采样稳定有效，它更可能反映了 Actor 的一般性缺陷，也更可能被转化为 Harness Extension。

### Registry Extension 可以逐步形成结构化流程

项目不在初始阶段预设复杂工作流。

相反，初始 Actor Core Loop 保持相对基础，通过可审计、可回滚的 Registry Extension，逐步发现小模型真正需要的约束和流程。

## 第一阶段研究边界

第一阶段聚焦于可重复、可比较的受控实验，而不是开放环境下的完整产品能力。

第一阶段默认使用：

- Controlled Corpus；
- Multi-hop QA；
- 固定一个小模型作为 Actor；
- 固定 Search、Open、Read 类基础工具；
- 固定 Agent Core Loop；
- 不产生外部副作用的工具调用；
- 可缓存的检索结果和工具输出；
- 可复现的 Rollout、Prefix-Fork 和 Harness Version。

第一阶段不直接使用开放网页搜索。开放网页内容和检索结果可能变化，会降低不同 Harness 版本之间的可比性，也会让收益来源难以归因。

## 非目标

第一阶段不以以下事项为目标：

1. 训练或微调 Actor 模型；
2. 构建开放 Web Search Deep Research Agent；
3. 构建通用 Agent 框架；
4. 让外部强模型参与最终在线推理；
5. 允许外部强模型直接修改 Agent Core Loop；
6. 允许外部强模型向 Actor 提供题目相关的 Query、实体、答案线索或证据路径；
7. 在第一阶段证明 Harness 对多个小模型普遍有效。

这些内容可以作为后续方向，但不属于第一阶段最小闭环的验收范围。

## 成功判据概览

当满足以下前提时，实验结果才具有解释意义：

- 未发生数据泄漏、评估篡改或审计绕过；
- 实验状态、数据可见性和评估过程符合既定协议；
- Rollout、Prefix-Fork 和 Harness 版本具有可追踪性与可复现性。

在此前提下，如果观察到以下现象，则认为实验结果支持项目假设：

- Soft Intervention 能稳定改善 Actor 行为；
- 有效干预能够被硬化为 Registry Extension；
- 最终 Hard Harness 在不调用外部强模型的情况下，相比 Actor-only Baseline 获得正确率提升；
- Hard Harness 在测试集和评估集上整体正确率提升，同时 Blind-OOD Eval Set 不出现明显退化；
- 随着 Harness Patch 积累，外部干预率下降，Soft-Hard Gap 缩小；
- Actor 的低级失败减少，失败类型逐步转向更高层的语义问题。

详细评估协议、数据划分和指标定义见 `evaluation.md`。
